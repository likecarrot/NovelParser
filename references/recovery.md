# 中断恢复与修订

续做先运行 `status`，读取当前卷、锁状态、章节、分镜与页数、缺失审查。项目统一使用 Schema v6。

## 剧本改动

`set-script` 或 `set-script-chapter` 导入新稿后，`script_lock` 立即失效，旧审查报告同时作废。必须重新执行三轮审查（coverage / continuity / comic）、补齐阶段审查，再 `lock-script`。

`impact --file <候选稿>` 可以对比新旧稿，列出受影响的分镜 ID，帮助你判断要重跑哪些章节的审查。

## 分镜描述改动

只改 `prompts/panels/*.json` 里的描述，不改 `project.json` 的 `script`，锁不会失效。但改完必须自查：

- 该格 `state_before` 是否仍接得上上一格的 `state_after`；
- 改动是否影响后续格的服装、伤势、持有物；
- 对白有没有被顺手改掉。

状态链断了就顺着往后修，不要只修一格。

## 外部原稿变动

外部原稿变动只作为警告，制作以归档副本为准。归档原文变化会阻断原有锁定，需要重新提取原文时，在当前卷 `versions/` 下建立新的独立状态，并维护 `current.json` 指向真实新状态。全部作品说明的剧情仍必须来自实际已读原文。

## 成品资产保护与删除二次确认

1. **已锁定分镜禁止乱删**：
   - `full-script.md`、`project.json`、`docs/`、`reports/` 是核心交付成果，**绝对禁止任何形式的随意删除、擅自清空或静默覆盖**。
   - 重新生成、版本迭代、异常恢复、日常清理中，已有交付物必须完整保留。
2. **删除唯一触发条件——用户明确要求**：
   - 严禁任何代理或脚本自行推定「文件已过期」或「清理空间」而删除交付物。
3. **强制二次确认机制**：
   - 即使用户明确要求删除，主代理也**不得直接执行物理删除**，必须先：
     - 列出拟删除的文件路径与所属卷次；
     - 说明该操作不可逆；
     - 明确询问：「是否确认删除已锁定的分镜剧本及相关交付文件？」；
     - 获得明确肯定答复后才执行；用户犹豫或不答复时立即终止。
